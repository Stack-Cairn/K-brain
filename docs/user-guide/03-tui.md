# TUI 与快捷键

运行 `kn` 进入终端界面。启动时顶部是欢迎卡片（版本、模型、工作目录和常用入口），下面是对话记录。输入框在底部，输入框下面的一行左侧是权限模式（以及 git 分支、目标、后台任务或临时提示），右侧是上下文占用和花费、模型和推理强度。有回合在运行时，输入框上方多一行状态：当前阶段及其用时、整轮用时、输出 token 数和 `Esc` 中断提示。有目标、计划或 subagent 时，顶部会出现一个可折叠的面板（`Ctrl+]` 或 `Alt+T`）。

在空输入框里按 `?`，或在任何时候按 `F1`，打开快捷键速查表（与 `/help` 相同，输入文字即可筛选；`/help text` 打印纯文本列表）。输入框里已有文字时，`?` 照常输入。

需要按两次的键（`Ctrl+C` 退出、`Esc Esc` 清空草稿或打开 rewind）在按第一次后，输入框下面那一行会短暂提示再按一次，过时或按了别的键后提示消失。

**Vim 模式（`/vim`）**

Vim 模式默认关闭，用 `/vim`（或 `/vim on` / `/vim off`）或 `/settings` 里的 “Vim mode” 打开，设置会保存。打开后输入框从插入模式开始，所有按键和平常一样；按 `Esc` 进入普通模式，信息栏显示 `-- NORMAL --`（插入模式显示 `-- INSERT --`）。普通模式下可打印的键是命令，不会输入文字；`Enter`、方向键、`Ctrl`/`Alt` 组合键和粘贴保持原来的作用。

| 快捷键 | 作用 |
|---|---|
| `h` / `j` / `k` / `l`（`Space` 同 `l`） | 左 / 下 / 上 / 右；在首行按 `k`、末行按 `j` 翻历史，和 `↑` / `↓` 一样 |
| `w` / `b` / `e` | 下一个词 / 上一个词 / 词尾 |
| `0` / `^` / `$` | 行首 / 第一个非空字符 / 行尾 |
| `x` | 删除光标处的字符 |
| `d`：`dd` / `dw`，`D` | 删除整行 / 删除到下一个词，`D` 删除到行尾 |
| `c`：`cc` / `cw`，`C` | 修改整行 / 当前词，`C` 修改到行尾（删除后进入插入模式） |
| `y`：`yy`，`p` | 复制整行；`p` 粘贴到光标后（整行内容粘贴到下一行） |
| `u` | 撤销 |
| `i` / `a` / `I` / `A` | 在光标前 / 光标后 / 行首 / 行尾进入插入模式 |
| `o` / `O` | 在下方 / 上方新开一行并进入插入模式 |
| `Enter` | 发送，下一条草稿回到插入模式 |
| `Esc` | 插入模式下进入普通模式；普通模式下是原来的 `Esc` |

`Esc` 的中断和回退语义保持不变，只是插入模式先吃掉一次：插入模式下 `Esc` 只切到普通模式；普通模式下输入框为空时 `Esc` 和关闭 vim 模式时一样，运行中立即中断，空闲时按两次打开回退。所以打开 vim 模式后，在空输入框里中断要按 `Esc Esc`，状态行会提示 `Esc Esc to interrupt`；`Ctrl+C Ctrl+C` 始终可用。补全菜单、排队消息和名称输入框打开时，`Esc` 先关闭它们。复制的内容只存在 vim 自己的寄存器里，不会写入系统剪贴板。

subagent 面板和 subagent 视图的按键见下文。

subagent 请求批准时，审批卡片标题写明是哪个 subagent（“Subagent · <描述> wants to run this command”）；几个请求同时等待时一次只显示一张卡片，标题后的 `+N pending` 表示后面还有几个。等待批准的 subagent 在对话记录和面板里显示 “waiting for approval”，计时暂停显示。

`/theme` 打开主题选择器（移动光标即预览，Enter 保存），`/theme <名称>` 直接切换配色（内置主题、自定义主题见[外观与状态行](13-appearance.md)），`/density compact|comfortable` 切换布局密度，`/language zh_cn|zh_Hant|en` 切换界面语言。

编辑、写入工具的结果和审批卡片里的差异中，相邻的删除行和新增行逐行配对，配对行里改动的词用更深的底色标出；终端只有 16 色或使用单色主题时改用反色显示，纯文本输出不加任何标记。两行差别太大（共同部分不足四成）时不标出词级改动。

在 tmux 里，`Shift+Enter` 需要 tmux 打开 `extended-keys`。`kn` 不会替你修改这个服务器级选项；没打开时启动会给出提示，`/doctor` 的 Terminal 一节也会显示当前状态。在 `~/.tmux.conf` 里加上 `set -s extended-keys on` 并执行 `tmux source ~/.tmux.conf` 即可；在此之前可以用 `Ctrl+J` 或 `Alt+Enter` 换行。

在 macOS 上，`Alt` 快捷键要求终端把 Option 键当作 Meta 键发送：Terminal 在“设置 › 描述文件 › 键盘”里勾选“将 Option 键用作 Meta 键”，iTerm2 在“Settings › Profiles › Keys”里把 Left Option key 设为 `Esc+`。没有设置时 Option+O 输入的是 `ø`、Option+T 输入的是 `†`，`kn` 无法把它们和正常输入的外文字符区分开，所以默认照常输入这些字符，只在它们第一次出现在空输入框时提示一次，`/doctor` 的 Terminal 一节给出设置方法。不想改终端设置的话，可以在 `/settings` 里打开 “Option as Alt”（默认关闭）：打开后美式键盘布局下 Option+A/B/D/F/K/M/O/T/Y/Z 输入的字符会被当作对应的 `Alt` 快捷键，这些字符也就无法再输入。Option+E 在美式布局下是死键，无法映射，请用 Meta 设置。常用的几个 `Alt` 键也有不需要 Option 的替代键：`Ctrl+F`（输入框为空时，代替 `Alt+O`）、`Ctrl+]`（代替 `Alt+T`）、`Shift+↑`（输入框为空时，代替 `Alt+↑`）、`Ctrl+E`（回合运行中且输入框为空时，代替 `Alt+E`）。

### 把命令移到后台（Ctrl+B）

`bash` 调用运行时，工具行右侧显示 `ctrl+b 后台运行`（英文界面为 `ctrl+b to background`）。此时按 `Ctrl+B`：

- 命令不会被结束或重启：进程、沙箱和输出都保持原样，输出继续写进日志。
- 这次工具调用立即返回，结果告诉模型：用户把命令移到了后台、它的 `process_id` 和日志路径、到此为止的输出末尾，以及之后用 `ManagedProcess`（`wait`、`read_log`、`status`、`stop`）读取或停止它。这个工具在第一次移到后台后才出现在模型的工具列表里，只能查看和停止，不能启动进程。
- 命令结束时，会话会收到一条通知（带退出码和最后的输出）；空闲时这条通知会启动新的一轮。
- 移到后台之后按 `Esc` 中断本轮不会结束这个命令。`/clear`、`/resume` 切换会话和退出 `kn` 会停止它。
- 同时有几个可移到后台的调用时，`Ctrl+B` 一次移走全部（实际上 `bash` 调用彼此串行，同一时刻最多一个）。子代理里的命令不受影响。
- 没有可移到后台的命令时（包括命令已经结束、或刚按过一次），`Ctrl+B` 仍是输入框里的光标左移。交互式（`interactive: true`）命令不能移到后台。

`Ctrl+B` 是固定键位，目前没有自定义快捷键的配置。它也是 tmux 的默认前缀键：在 tmux 里要连按两次 `Ctrl+B`（tmux 把第二次按键原样发给 `kn`），或者改用别的 tmux 前缀。

## 会话总览

`/dashboard`（或 `Ctrl+P` 命令面板中的 **Dashboard**）打开全屏的会话总览：当前工作区和其他工作区的会话、各自的状态、模型、令牌与最后活动时间，以及本会话的 subagent。`Enter` 打开会话，`n` 新建，`d` 删除，`/` 筛选，`Tab` 按工作区分组，`r` 刷新。详见[会话总览（Dashboard）](14-dashboard.md)。

## Subagent 面板与实时视图

前台和后台 subagent 都会出现在输入框下方的面板里：运行中的排在前面，已结束的随后，各组内新的在前。底部状态栏的 `⚙ N sub` 统计正在运行的 subagent 数量（含前台）。

对话记录中，每个 subagent 调用下方有一行实时状态：

```
● Subagent(Survey the loader)
  ⎿ ◌ running · 2 tools · Grep(LoadConfig) · 12s · 3.4k tok · Ctrl+T view
```

后台任务的状态行会显示任务 ID，结束后变成 `⎿ ✓ <id> done · 5 tools · 43s · 12.3k tok`。后台完成通知以状态行（`◆ subagent <id> done · …`，报告默认折叠，`Ctrl+F` 或 `Alt+O` 展开）显示，不会显示成用户输入；它以后台消息身份发给模型。

| 按键（面板聚焦时） | 作用 |
|---|---|
| `↑` / `↓` | 选择 subagent；在首行按 `↑` 回到输入框 |
| `Space` | 在面板内预览最近输出 |
| `Enter` | 打开该 subagent 的实时记录视图 |
| `Ctrl+X` | 停止选中的后台 subagent（前台 subagent 用 `Esc` 中断整个回合） |
| `Ctrl+T` | 回到输入框 |

| 按键（subagent 视图中） | 作用 |
|---|---|
| `Enter` | 运行中：补充指令（steer）；已结束：续聊（follow-up）。前台 subagent 只读 |
| `Ctrl+X` | 停止该 subagent 或当前续聊 |
| `PgUp` / `PgDn`、`↑` / `↓` | 滚动；`Ctrl+Home` / `Ctrl+End` 跳到开头 / 最新 |
| `Esc` / `Ctrl+T` | 返回主界面，焦点留在面板 |

## 屏幕模式与终端输出

### 内联模式

默认情况下 `kn` 在终端的备用屏幕（alternate screen）里运行：对话记录由 `kn` 自己滚动，退出后终端恢复原样，对话不留在终端里。内联模式改为直接在普通屏幕里运行：

- 已经定型的内容（你的消息、结束的回复、完成的工具调用、通知等）只打印一次，进入终端自己的滚动缓冲区。之后用终端的滚轮、搜索和选择查看它们，退出 `kn` 后也仍然留在终端里。
- 底部只有实时区域会重绘：正在流式输出的回复、运行中或排队的工具、仍在到达的思考、subagent 面板、状态行、权限和提问等对话框，以及输入框。

开启方式（任选其一）：

| 方式 | 说明 |
|---|---|
| `kn --inline` | 本次启动使用内联模式；`kn --inline=false` 强制使用备用屏幕，优先于配置 |
| 配置项 `"inline": true` | 写入 `config.json`，见[配置](05-configuration.md) |
| `/settings` 的 Display → Inline mode | 切换并保存上面的配置项，下次启动生效 |

`/doctor` 的 Terminal 一节显示当前屏幕模式（`screen inline …` 或 `screen alternate screen`）。

什么时候打印：

- 回复在流式输出期间留在实时区域，整条回复结束后一次性打印。
- 工具调用运行中或排队时留在实时区域；结束并拿到结果（耗时、退出码）后打印。回合进行中，末尾连续的只读调用（read、grep、glob、web_fetch 等）还可能合并成一组，因此要等到后面出现其他内容或回合结束才打印。
- 内容严格按顺序打印：一个块还在实时区域时，它之后的块也都留在实时区域。
- 已打印的块之后又发生变化时，不会修改已打印的内容，而是补打：对已打印的工具块按 `Ctrl+F` 或 `Alt+O` 展开，会再打印一份展开后的版本；后台 subagent 结束时，再打印一行它的最终状态。
- `/clear`、`/resume`、rewind、fork、导入会话、撤销压缩等会重建对话的操作：先打印一条分隔线，再打印重建后的完整对话（`/resume` 即为恢复提示加上历史全文）。滚动缓冲区是内联模式唯一的历史记录，因此选择打印全文而不是摘要，以便在终端里搜索。分隔线以上的旧内容不会被清除。
- 调整窗口大小和 `Ctrl+L` 只重绘实时区域，从不重新打印历史。
- 退出时清除实时区域，并把还没打印的内容（例如被中断的回复）补打出来。

需要整个屏幕的视图（`Ctrl+P` 命令面板、会话与模型选择器、`/settings` 等界面、任务视图、`Shift+↑` / `Alt+↑` 聚焦对话记录、全屏查看块）打开时会临时切换到备用屏幕，关闭后回到原处；期间完成的内容在返回时打印。

内联模式下本次会话不启用鼠标捕获（配置中的 `mouse` 不受影响），滚轮和拖选交给终端。`PgUp` / `PgDn` 不滚动对话，请用终端自己的滚动（例如 `Shift+PgUp`）。

限制：

- 已打印的内容不能再折叠、展开或更新，只能补打新版本；切换主题不会给已打印的内容重新上色。
- 在会重新排版（reflow）的终端里把窗口变窄时，旧的实时区域可能有一部分残留在滚动缓冲区中；`Ctrl+L` 只能修正当前屏幕。
- 很长的回复在结束前只显示末尾能放进屏幕的部分，结束后才完整进入滚动缓冲区。
- rewind、fork 等操作会重新打印对话，滚动缓冲区里会同时有旧版本和新版本，以分隔线隔开。

### 同步输出

支持 DEC 私有模式 2026（同步输出）的终端可以把一帧完整地一次显示出来，避免重绘时出现半帧画面或闪烁。`kn` 启动时判断是否启用，启用后每一帧前后加上 `ESC[?2026h` / `ESC[?2026l`：

1. 环境变量 `K_BRAIN_SYNC_OUTPUT=1`（或 `on`、`true`、`yes`）强制开启，`K_BRAIN_SYNC_OUTPUT=0`（或 `off`、`false`、`no`）强制关闭。
2. 在 tmux 里按 tmux 版本决定：3.4 及以上由 tmux 自己实现该模式，序列直接发给 tmux，不经 passthrough 转发给外层终端；更早的版本关闭。
3. GNU screen 和 mosh 中关闭。
4. 其他情况下向终端发送 DECRQM 查询（`ESC[?2026$p`，后跟一个所有终端都会应答的 DA1 查询），终端报告支持该模式才开启；不支持或 500 毫秒内没有应答则关闭。

`/doctor` 的 Terminal 一节显示结果和依据，例如 `synchronized output  on (terminal reports mode 2026)`。

查询需要在启动时与终端往返一次。如果终端响应很慢，或者在某个终端里看到异常，可以用 `K_BRAIN_SYNC_OUTPUT=0` 关闭；Windows 上不发送查询，需要时用 `K_BRAIN_SYNC_OUTPUT=1` 开启。
